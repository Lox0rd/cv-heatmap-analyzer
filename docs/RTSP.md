# Работа с RTSP-видеопотоками

## 1. Обзор

RTSP (Real Time Streaming Protocol) — протокол управления потоковой передачей мультимедиа. Он часто используется для получения видео с IP-камер, систем видеонаблюдения и медиасерверов.

В `cv-heatmap-analyzer` RTSP позволяет получать видеоданные непосредственно из сетевого источника и использовать их для последующей обработки.

В отличие от локального видеофайла, сетевой поток может временно становиться недоступным, иметь задержку или прерываться из-за проблем с сетью. Поэтому при работе с RTSP важно учитывать состояние соединения и доступность кадров.

## 2. Формат RTSP-адреса

Обычно адрес потока выглядит следующим образом:

```text
rtsp://<host>:<port>/<path>
```

Где:

- `host` — IP-адрес или доменное имя камеры либо медиасервера;
- `port` — порт RTSP-сервера, часто `554`;
- `path` — путь к конкретному видеопотоку.

Пример условного адреса:

```text
rtsp://192.168.1.100:554/stream1
```

Некоторые камеры требуют авторизацию. В таком случае адрес может включать имя пользователя и пароль:

```text
rtsp://<username>:<password>@<host>:<port>/<path>
```

Точный адрес зависит от производителя камеры и её настроек. Его следует искать в документации устройства или в настройках камеры.

**Важно:** не публикуйте реальные адреса камер с учётными данными в репозитории, логах или скриншотах.

## 3. Подключение к IP-камере

Перед подключением убедитесь, что:

1. Камера включена и доступна по сети.
2. На камере активирован RTSP, если это необходимо для конкретной модели.
3. Компьютер имеет сетевой доступ к камере.
4. Используется правильный RTSP-адрес.
5. Учётные данные указаны корректно, если камера требует авторизацию.

После проверки передайте адрес потока в приложение способом, предусмотренным текущей реализацией `cv-heatmap-analyzer`.

Например, если используется класс `VideoProcessor`:

```python
from src.video.video_processor import VideoProcessor

stream_url = "rtsp://192.168.1.100:554/stream1"

video = VideoProcessor(stream_url)

try:
    for frame in video.read_frames():
        if frame is None:
            continue

        # Здесь можно выполнять обработку кадра.
        pass
finally:
    video.release()
```

Этот пример иллюстрирует общий сценарий работы. Названия методов и поведение при потере соединения должны соответствовать текущей реализации `VideoProcessor`.

## 4. Локальное тестирование без IP-камеры

Для проверки RTSP-подключения можно использовать MediaMTX. Он позволяет создать локальный RTSP-сервер и отправлять в него тестовое видео.

Для этого потребуются:

- установленный Docker;
- FFmpeg;
- тестовый видеофайл, например `tests/data/test.mp4`.

### Шаг 1. Запустить MediaMTX

В отдельном терминале выполните:

```bash
docker run --rm -it \
  -p 8554:8554 \
  bluenviron/mediamtx:latest
```

Сервер будет принимать RTSP-подключения на порту `8554`.

### Шаг 2. Отправить видео на сервер

Откройте второй терминал в корне проекта и выполните:

```bash
ffmpeg -re -stream_loop -1 \
  -i tests/data/test.mp4 \
  -an \
  -c:v libx264 \
  -preset ultrafast \
  -tune zerolatency \
  -r 25 \
  -f rtsp \
  -rtsp_transport tcp \
  rtsp://localhost:8554/test
```

Команда циклически отправляет тестовое видео на RTSP-сервер.

Параметры:

- `-re` — считывает файл примерно с исходной скоростью воспроизведения;
- `-stream_loop -1` — повторяет видео бесконечно;
- `-an` — отключает передачу звука;
- `-c:v libx264` — кодирует видео в H.264;
- `-preset ultrafast` — уменьшает вычислительную нагрузку при кодировании;
- `-tune zerolatency` — настраивает кодирование для низкой задержки;
- `-r 25` — задаёт частоту кадров 25 FPS для выходного потока;
- `-rtsp_transport tcp` — использует TCP для передачи RTSP-медиаданных.

Если FFmpeg сообщает, что файл не найден, проверь путь к тестовому видео.

### Шаг 3. Подключиться к потоку

В приложении используй адрес:

```text
rtsp://localhost:8554/test
```

Если приложение запущено на другом компьютере, вместо `localhost` укажи IP-адрес компьютера, на котором работает MediaMTX. Также убедись, что порт `8554` доступен по сети.

### Шаг 4. Проверить результат

Убедись, что приложение получает кадры и может передавать их в дальнейшую обработку.

Для проверки самого потока без приложения можно использовать FFmpeg:

```bash
ffplay -rtsp_transport tcp rtsp://localhost:8554/test
```

Для остановки отправки видео нажми `Ctrl+C` в терминале FFmpeg. Для остановки MediaMTX нажми `Ctrl+C` в терминале сервера.

## 5. Транспорт TCP и UDP

RTSP может использовать разные способы передачи медиаданных.

| Транспорт | Особенности |
|---|---|
| TCP | Более надёжная доставка данных, часто удобна для диагностики сетевых проблем |
| UDP | Может обеспечивать меньшую задержку, но пакеты могут теряться в сети |

Для первоначального тестирования рекомендуется TCP. Он часто упрощает работу через сети с ограничениями на передачу UDP-пакетов.

Фактическая поддержка транспортов зависит от камеры, медиасервера и используемой конфигурации OpenCV/FFmpeg.

## 6. Типичные проблемы

### Не удаётся подключиться к потоку

Возможные причины:

- неправильный RTSP-адрес;
- камера или сервер выключены;
- порт недоступен;
- отсутствует сетевой маршрут до камеры;
- неверные учётные данные.

Проверь доступность устройства и правильность адреса. Если используется удалённая камера, убедись, что сеть разрешает подключение к её RTSP-порту.

### Подключение устанавливается, но кадры не поступают

Проверь, действительно ли камера публикует видео по указанному адресу. Для диагностики попробуй открыть поток через `ffplay` или другой RTSP-клиент.

Также проверь кодек видео и сообщения OpenCV/FFmpeg: не все сборки поддерживают одинаковые форматы и способы передачи.

### Поток периодически прерывается

Причиной могут быть нестабильная сеть, перезапуск камеры или перегрузка устройства.

При проектировании обработки следует учитывать возможность временной потери кадров и соединения. Если `VideoProcessor` поддерживает переподключение, проверь, что оно работает после восстановления потока.

### Большая задержка

Задержка зависит от камеры, кодека, сетевого соединения, буферизации и параметров декодирования.

Для диагностики сначала проверь поток в отдельном RTSP-клиенте. Затем сравни результат с работой приложения. Не меняй одновременно несколько параметров — так проще определить причину задержки.

## 7. Безопасность

При работе с сетевыми камерами соблюдай следующие правила:

- Используй отдельные учётные данные с минимально необходимыми правами.
- Не сохраняй пароли камер в исходном коде.
- Не добавляй реальные RTSP-адреса с логином и паролем в Git.
- Храни секреты в переменных окружения или другом подходящем хранилище.
- Не открывай RTSP-порт в интернет без необходимости.
- Для удалённого доступа предпочитай VPN или другую защищённую сетевую инфраструктуру.

Если RTSP-адрес с паролем попал в публичный репозиторий, считай пароль раскрытым и замени его.
